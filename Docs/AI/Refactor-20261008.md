# Dragon MMA Idle — 연출 코드 리팩토링 / 2026-10-08

## 결과와 범위

기준 커밋: `f219bae7592e59a8e1c245899c5fe78d9803dfff` (`Initial import: Dragon MMA Idle (project08)`).
사용자 요청에 따라 구조 정리 후 검수하고, 일반 fast-forward commit·push한다. Git 이력을 다시 초기화하거나 force-push하지 않는다.

이번 작업은 **동작 보존 리팩토링**이다. 승인된 잽·새끼용 피격 그림, 첫 전투 스토리라인, 포획/패배 연결을 유지한다. 그래픽 품질이나 재미가 개선됐다는 주장이 아니라, 다음 연출 개선을 작은 단위로 수정하고 검수하기 위한 구조 정리다.

## 구조 변경

- `Scripts/DragonMmaView.cs`: 기존 직렬화 필드, 동일 MonoBehaviour/GUID, 초기화·해제·버튼 바인딩·공개 API 유지. 한 파일 약 700줄에서 약 270줄로 축소.
- `DragonMmaView.Panels.cs`: 수용소·훈련·시장·기술 패널 데이터 렌더링. 기존 메서드 본문을 그대로 이동.
- `DragonMmaView.CombatFeedback.cs`: 타격 VFX·오디오·상태 라벨·픽셀 정렬 적용. 순수 연출 계산과 분리.
- `DragonMmaView.Presentation.cs`: 사냥/월드/훈련 적용을 별도 메서드로 분리. 포획 시 승객 중심을 조준하는 계산을 공통화하되, 접촉 프로필의 체형 보정 전후에 다시 계산하는 순서는 유지.
- `HuntPresentation.cs`: 세션 상태와 런타임 설정을 읽어 포즈·동선·문구·포획/회복 연출 프레임을 반환하는 정적 C# 계산. 세션 Tick, 승패 결정, 보상 지급, 파일/리소스 로드 권한을 추가하지 않음.
- `BabyFirstBattle.cs`: 잽/위협 구간 평가를 별도 함수로 분리하고 가드·위협 시간 상수에 이름 부여. 기존 값·연산·출력 보존.
- `Tests/Editor/HuntPresentationTests.cs`: 연출 계약 31개 추가.
- `Editor/RefactorRegressionQa.cs`: 변경 전후 타임라인/실제 메인 뷰 특성 기록과 비교 도구. Editor 전용이며 Play+Pause+격리 저장이 없으면 실행을 거부.

partial 파일은 별도 컴포넌트가 아니다. Inspector에서 다시 연결할 필드는 없고, 새 매니저/전투 상태 머신도 없다. `DragonGameSession`이 게임 상태의 유일한 판정 주체인 경계를 유지한다.

`comparison.txt`와 before/after 파일은 실제 비교 결과다. 샘플 검수는 매 샘플 격리 상태를 설정하며, 메인 게임 전체를 연속 재생한 영상/입력 테스트가 아니다. 환경 시계에 의존하는 speed-line pulse 색은 비교에서 제외했다. 실시간 3회 검수는 메인과 같은 타임라인을 쓰는 Animation Lab이지 세션 승패 시뮬레이션이 아니다.

### 검수 중 발견·수정한 사항

- 새 Editor QA의 LINQ 오버로드가 Unity .NET 프로필에 없어서 첫 컴파일에 실패했다. `Where(...).DefaultIfEmpty(-1).First()`로 교체 후 import·실행 성공.
- 첫 변경 후 테스트는 완료 전에 Play 진입해 assembly reload로 중단됐다. 오래된 217개 XML을 성공 근거로 사용하지 않았다. 이후 Play 전환 없이 재실행하고 새로운 248개 결과의 시간·실패 수를 확인했다.
- 임시 패널 검수 명령의 DTO 이름 `TrainingSlot`은 프로젝트에 없었다. 기존 `TimedDragonSlot`으로 고친 뒤 실행해 통과했다. 프로젝트 코드 수정/런타임 결함이 아니라 검수 명령 컴파일 실패다.

## 보존과 제한

- 기존 `.meta`와 씬/프리팹, 스프라이트/원본, 클립/컨트롤러, 게임 밸런스/설정, 저장 DTO/세션, Packages/ProjectSettings는 변경하지 않았다. 새 소스에 대해서만 Unity가 `.meta`를 생성했다.
- 게임 사용자 저장에 접근하지 않도록 격리 저장 경로를 사용했고, 검수 종료 후 해제했다. 이전 첫 전투/BASIC JAB 원시 검수 로그는 백업 후 복원하여 보존했다. 최종 Editor는 stopped, clean DesktopOverlayScene이다.
- exe 실제 실행/네이티브 창·클릭스루·실물 터치/장치·Steam·브라우저/새 WebGL 배포는 이번 검수에 포함되지 않는다. 기존 WebGL IL2CPP AnalyticsWriter 메모리 부족 문제는 해결한 것이 아니다.
- 프레임 성능/할당량을 측정하지 않았으므로 성능 향상을 주장하지 않는다. 기존 per-Tick 리소스 로드 없음 경계는 유지했다.
- Unity implementation/build-validation/MCP skills의 직렬화 안전성·변경 전 기준선·증거 수준 구분을 적용했다. 그 결과 자산 재생성 대신 동일 컴포넌트 구조 분리와 전후 특성 비교를 선택했다.
