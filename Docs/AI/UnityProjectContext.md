## Current implementation — 2026-10-01 upgrade

- `DragonData.cs`: five-species catalog, encounter gates/pity, version-2 save DTOs, individual dragon IDs, v1 migration, atomic save plus backup.
- `DragonGameSession.cs`: deterministic hunting/return/training/market state machine. UI subscribes to `Changed` and `Notify`; tests inject randomness and UTC time.
- `DragonMmaGame.cs`: Unity lifecycle, Input System and explicit UI-hit exclusion, save adapter. Space is the only keyboard cheer key. Read input before the final battle tick.
- `DragonMmaView.cs`: serialized scene/prefab MonoBehaviour. No runtime UI construction. Binds authored pages with DragonUiBindings, updates data/visibility and additive motion relative to placed actors. Management expands above hunting without pausing it. Do not unconditionally disable/re-enable visible pages on Refresh: this restarts Animator.
- `DragonGameConfig.cs` / `Configuration/DefaultGameConfig.asset`: Inspector-authored species stats, economy, durations, chance/cheer and pity. Each session uses a deep validated snapshot. Existing saves keep progress; new-save settings only affect new saves.
- `DragonActorView.cs`: authored root transform + child Visual Image/Animator. As of the 2026-10-02 fighter upgrade, `Animations/` contains six controllers and 27 sprite clips: 12 fighter poses (idle/walk loop; 10 one-shots) plus the 15 original looping dragon clips. Fighter visuals rotate at the foot pivot; dragon root rotation remains unchanged. `Prefabs/` contains 16 UI/actor/facility prefabs, with OverlayRoot as the complete screen root.
- `DragonMmaSceneAuthoring` / `DragonMmaLayoutSeed`: EDITOR-only one-time migration; refuses to overwrite an already authored scene. Do not use generation for ordinary layout changes. Edit scene/RectTransforms/prefabs instead.
- `Fonts/NanumGothic-Regular.ttf`: persistent bundled Korean font, OFL included. OS dynamic Font objects saved as fontsettings lose rendering resources; do not replace with that pattern.
- `DesktopOverlayWindow.cs`: Windows-only borderless/topmost work-area docking, 360/720 reference heights at 1080p, monitor/DPI polling, screen-pixel input regions. Touch hardware uses native per-pixel color-key hit testing.
- `DragonPixelArtUpgrade.Generate()`: legacy global generator. Skips fighter frames after the reference-based upgrade is installed, but still regenerates other art. Use `FighterReferenceUpgrade.Import()` for fighter-only regeneration; never use the global generator when dragons must be preserved.
- `DragonMmaProjectBuilder.BuildProject()`: legacy new-project scaffold only; refuses to overwrite any existing scene. New scenes are converted to authored assets before use.
- `DragonMmaValidation`: EditMode suite and Windows Development build to `Builds/Windows-Upgrade/DragonMMAIdle.exe`.
- `DragonMmaUpgradeValidation`: isolated Play Mode saves and render capture helpers. Call `EndIsolation()` after QA.
- `DragonMmaPlayerProbe`: opt-in Development-only `-dragonProbe -dragonTestSave <absolute-path>` native window/backbuffer validation, then exits. Never enabled on a normal launch.

## Authoritative behavior

Design: `../# Dragon MMA Idle v0.1.txt`. Fresh game starts with 0G, fighter power10, training locked for80G. Baby is the first encounter. Later species unlock only after the previous species is captured. Pity starts at that capture. Combat20s, walking10s, defeat+recovery10s; cheer +0.2 percentage points/input, maximum+10. Cargo transfers immediately on return, independently of the exit animation. Each individual grants training cores once; each species grants power/skill once. Completed trainees remain in the room. Offline only completes existing facility timers; selling still needs manual claim.

## Windows rendering contract

Force D3D11 and `PlayerSettings.useFlipModelSwapchain=false`; disable fullscreen switching. Camera has no HDR/MSAA/postprocessing and clears to exact black, matching `LWA_COLORKEY=0`. Reserve pure opaque black in all art/UI; use the dark blue-green palette for visible outlines. Negative space then passes through natively; UI and battle surfaces receive input. Primary monitor is selected; an in-game monitor selector, physical touch testing, and Steam integration testing remain future work.
