# 전투 디렉팅 QA 오판 회고

## 증상

자동 테스트와 빌드는 통과했지만 실제 전후 화면에서 전투의 체감 크기, 충돌감, 화면 밀도는 거의 달라지지 않았다.

## 확인된 원인

1. **정확성과 품질을 같은 것으로 취급했다.** 166개 테스트의 대부분은 게임 규칙, 에셋 연결, 프레임 수, GUID, 상태 전환을 검증했다. 이는 회귀 방지에는 유효하지만 전투가 더 재미있고 강하게 보이는지는 증명하지 않는다.
2. **화면 비중을 UI 사각형 수치로만 판정했다.** 전투 입력 영역은 커졌지만 실제 데스크톱 창 높이는 360px, Web 기준 높이는 420px 그대로였다. 결과적으로 1920×720 캡처의 상단 절반 이상이 계속 비어 있었다.
3. **동일 조건 전후 비교가 아니었다.** 이전 보고서의 before/after는 용 종류, 전투 시점, 능력치가 달랐다. 따라서 시각적 개선을 비교하는 증거로 사용할 수 없었다.
4. **정지 이미지 존재를 시각 QA로 오인했다.** 캡처 파일 생성과 해상도만 확인했고, 캐릭터 점유율, 콘텐츠 세로 범위, 접촉 중심, 다층 VFX, 예비동작-접촉-회복의 프레임 차이를 평가하지 않았다.
5. **히트스톱·상태 라벨 같은 미세 변경을 과대평가했다.** 같은 스프라이트와 단일 작은 스파크를 유지한 상태에서 타이밍 수치만 바뀌었기 때문에 실제 체감 차이가 제한적이었다.
6. **테스트 개수로 신뢰도를 표현했다.** 전체 통과 개수는 시각 품질 항목의 수나 강도를 뜻하지 않는데도 최종 판단에서 과도하게 사용했다.
7. **렌더 성공 여부를 먼저 검증하지 않았다.** `-nographics` 실행에서 생성된 1920×720 단색 회색 이미지를 기존의 “상단 밝은 픽셀” 지표가 가득 찬 화면으로 오인했다. 파일 존재·해상도·밝은 픽셀만으로는 유효한 캡처를 증명할 수 없다.

## 반증 실험

기존 개선본에 새 `CombatDirectingQualityTests`를 적용했다.

- 5개 중 4개 실패
- Desktop `huntReferenceHeight`: 요구 500px 이상, 실제 360px
- Web `huntReferenceHeight`: 요구 650px 이상, 실제 420px
- Desktop/Web 모두 포커스 배경, 프레임, 리듬 라벨, impact ring/echo/dust, 속도선 없음
- 기준선: `Artifacts/CombatDirectingRedo-20261007/baseline-quality-results.xml`

이 결과는 “기존 QA가 잘못된 대상을 측정했다”는 가설을 지지하고, 단순 취향 차이 또는 캡처 오류 가설을 약화한다.

## 새 QA 합격 조건

### 구조·점유율

- Desktop 전투 뷰 기준 높이 ≥ 500px
- Web 전투 뷰 기준 높이 ≥ 650px
- 전투 입력/연출 영역 높이 Desktop ≥ 300px, Web ≥ 380px
- 100% 배율에서 파이터 가시 높이 ≥ 180px, 선택 Baby 용 ≥ 115px
- Web은 파이터 가시 높이 ≥ 165px, 선택 Baby 용 ≥ 105px

### 연출 레이어

- 전투 포커스 배경과 상·하 프레임
- 현재 교전 리듬 라벨
- burst + ring + echo + dust의 독립 충돌 레이어
- 최소 5개의 예고/속도선
- 예비동작, 접촉, 후속 회복에서 서로 다른 루트 스케일과 위치

### 동일 조건 비교

- 같은 해상도 1920×720
- 같은 Baby 용
- 같은 Power 교전의 같은 접촉 시점
- 같은 초기 저장 데이터와 승률
- before/after 콘텐츠 세로 범위와 변경 픽셀 비율을 기록
- anticipation/contact/follow-through 연속 캡처 생성
- 시각 캡처는 그래픽 장치를 활성화한 배치에서 생성하고 `-nographics` 결과를 품질 증거로 사용하지 않음
- 모서리 배경색과 다른 픽셀 비율이 2% 미만이면 단색/공백 캡처로 즉시 실패

### 최종 판정

- 자동 테스트 통과만으로 Ready 판정 금지
- 실제 Play Mode 캡처를 사람이 100% 크기로 확인
- VFX 중심이 피격 캐릭터와 일치하는지 확인
- 효과음은 트리거·중복뿐 아니라 약/방어/강/다운 구분을 실제 재생 시나리오에서 확인
- Windows 플레이어 빌드와 실제 실행 화면을 함께 검증

## 재작업 결과

- 강화 품질 게이트: 8/8 통과
- 전체 EditMode 회귀: 174/174 통과
- 동일 Baby/Power 시나리오의 실제 1920×720 콘텐츠 상단: 356px → 511px, +155px
- 배경과 구분되는 픽셀 비율: 30.9% → 50.4%
- anticipation/contact/follow-through 3프레임을 각각 생성하고 100% 크기로 직접 확인
- Windows 플레이어 빌드 성공: errors 0, warnings 2

이 수치는 품질 그 자체의 대체물이 아니라 최소 반증 장치다. 최종 Ready 판정은 구조 게이트, 유효한 동일 조건 캡처, 사람의 시각 확인, 전체 회귀, 플레이어 빌드가 모두 통과할 때만 내린다.
